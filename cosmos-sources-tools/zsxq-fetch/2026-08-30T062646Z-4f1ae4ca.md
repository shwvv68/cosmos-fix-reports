## Why the change was needed

The current official web UI can render downloadable file cards without the previously required stable file-ID attribute. The active collector failed closed with `FILE_ATTACHMENT_MISMATCH`; expected behavior is to inventory and download those cards without weakening topic or filename verification.

## Reproduction

1. Open a signed-in official web timeline containing a file attachment card without the stable file-ID attribute.
2. Run the active browser inventory adapter.
3. Observe that the previous contract rejects the card before inventory can complete.

## Changed packaged paths

- `skills/zsxq-fetch/scripts/zsxq-browser-collector.mjs`: added contract v10, using a topic-local ordinal identity only when a file card has no platform ID; retained v9 strict behavior and preserved topic identity, ordinal, filename, preview-name, and official-UI download verification.
- `skills/zsxq-fetch/tests/zsxq-browser-collector.test.mjs`: added coverage for ordinal fallback, v9 strictness, invalid nonempty IDs, and safe download re-resolution.
